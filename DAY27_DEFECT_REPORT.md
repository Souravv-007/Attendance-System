| D27-001 | HR attendance management | Applying both an employee and a department filter returned all attendance in the selected department rather than only that employee’s attendance. | HIGH | Sign in as HR; select an employee and a department containing other employees; apply filters. | The department branch overwrote the existing `employee` query filter. | Intersect the selected employee ID with the department employee IDs. | Passed: the Day 27 integration test verifies the response contains only the selected employee’s record. |
| D27-002 | HR employee edit dialog | A profile name, email, or department name containing HTML could be inserted into the dialog markup and execute when an HR user opened the edit dialog. | HIGH | Set a profile name containing an attribute-breaking HTML payload; as HR, open Employees and select Edit for that user. | Untrusted values were interpolated directly into `innerHTML` attribute and option content. | Escape all dynamic edit-dialog attribute and option values before interpolation. | Passed: frontend regression test verifies dynamic edit values are escaped before insertion. |
| D27-003 | Logout/session handling | Logout depended on individual page scripts, while HR and Admin dashboards exposed no logout control. A page-script error could also leave an existing control without its listener. | HIGH | Sign in as HR or Admin and open the role dashboard; no logout action is available. | Session clearing and redirection were duplicated in employee page scripts instead of the shared authentication utility. | Add one shared `data-logout` listener in `api.js`, remove duplicate page listeners, and add the control to HR and Admin dashboards. | Passed: logout tests verify key removal, redirect, protected-page redirect, relogin storage, and role dashboard mapping. |
